# Muslingo: итоговый production-аудит

Дата: 11 августа 2026  
Локальный commit: `fe7fd1c`  
Production: <https://muslingo-mobile.vercel.app>  
Vercel deployment: `dpl_As35S3yDezJvc6wsP1LVUm3tV4Us`

## Результат

Актуальная production-версия опубликована и проверена на старом браузерном
профиле, на котором раньше открывался устаревший интерфейс. Корневая причина
была в старом Flutter service worker: установленная PWA продолжала отдавать
закэшированный `main.dart.js`. Теперь bootstrap и retirement worker не
кэшируются, старый worker принудительно обновляется, снимает регистрацию и
перезагружает приложение. Локальный прогресс при проверке сохранился.

В приложении ровно 100 уроков:

- 68 уроков по Корану;
- 22 урока арабского чтения;
- 10 уроков по основам ислама.

Три режима переключаются без конфликта. Путь уроков прокручивается внутри
фиксированной панели, поэтому Академия, аят дня и учебная цель доступны без
пролистывания всех 100 уроков.

## Исправлено

### Произношение

- Одна буква больше не принимается за полный аят: production вернул `score: 1`
  и `passed: false` для одной буквы против полной фразы.
- Клиентская и серверная text/STT-оценка используют одинаковый штраф за
  недостаточное покрытие фразы.
- Перед записью пользователь обязан прослушать образец.
- Результат честно обозначен как образовательная text/STT-оценка, а не как
  квалифицированная проверка таджвида по фонемам.

### Прогресс, XP и Лига

- Завершение урока требует подписанный сервером lesson attempt.
- Неподписанный `complete` отклоняется с HTTP 400.
- Повтор одного attempt не начисляет XP второй раз (`replayed: true`, `xp: 0`).
- Клиентский guest import не может подменить список уроков, XP, уровень и streak.
- Weekly XP имеет серверный дневной лимит; записи Лиги не раскрывают UUID.
- League и Friends честно требуют backend-аккаунт у локального профиля.

### Авторизация и данные

- Лимиты входа и регистрации стали атомарными.
- Logout отзывает JWT на сервере; старый token после выхода возвращает 401.
- Удаление аккаунта удаляет пользователя и связанные push-подписки; token после
  удаления возвращает 401.
- Локальные пароли используют усиленный PBKDF2, старые хеши обновляются после
  успешного входа.

### Push и навигация

- Web push привязывается к авторизованному аккаунту и installation ID.
- Подписка удаляется при logout и удалении аккаунта.
- Добавлены квоты и проверка разрешённых push endpoint.
- Native notification обрабатывает cold start и передаёт маршрут приложению.
- Тексты уведомлений зависят от streak, повторений и учебной цели.

### Доставка и CI/CD

- Vercel использует закреплённые Flutter `3.44.6`, Node `24.x` и pnpm `9.15.9`.
- GitHub Actions закреплены по commit SHA и работают с минимальными правами.
- Android release больше не может незаметно собраться с debug-подписью.
- APK-кнопка скрыта, пока реальный подписанный artefact не существует.
- Устаревшая PWA автоматически переходит на новую production-версию.

## Внешние блокеры

Это не ошибки кода, их нельзя завершить без владельца аккаунтов или секретов.

1. **GitHub:** локальная `main` опережает `origin/main` на 22 commit. Для push
   нужно один раз выполнить `gh auth login` на этом Mac или настроить Git
   credentials. Текущий GitHub CLI не авторизован.
2. **Подписанный Android APK:** в GitHub Secrets нужны
   `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`,
   `ANDROID_KEY_PASSWORD`, `ANDROID_KEY_ALIAS`. После push workflow создаст
   скачиваемый APK и checksum; приложение автоматически покажет кнопку.
3. **Remote AI Coach:** в Vercel Production отсутствует `GROQ_API_KEY`.
   До его добавления работает локальный персональный Coach без отправки данных
   внешнему провайдеру.
4. **Native iOS:** нужен Apple Developer аккаунт, Team ID, сертификаты и
   provisioning profile. Сейчас на iPhone полноценно работает устанавливаемая
   PWA, но TestFlight/App Store artefact не выпущен.
5. **Юридические данные:** в privacy-документах нужно заменить placeholders на
   название оператора, контакты, страну/адрес и правила пожертвований.

## Осознанные ограничения

- Проверка речи пока сравнивает распознанный текст с образцом. Для настоящей
  Duolingo-подобной оценки фонем и махраджа нужен внешний speech/audio pipeline,
  согласие на обработку голоса и экспертно проверенные критерии таджвида.
- Apple/Google/phone login, password recovery, email verification, реальные
  платежи Muslingo+ и donations ещё не подключены и не выдаются UI за готовые.
- `flutter_tts 4.2.5` даёт предупреждения Wasm dry run. Production JavaScript
  build работает; переход на Wasm требует совместимого обновления пакета.
- В in-app browser зафиксировано предупреждение загрузки Roboto с Google Fonts,
  но прямой production-запрос к файлу возвращает HTTP 200, интерфейс не падает
  и использует встроенные Nunito/Amiri.
