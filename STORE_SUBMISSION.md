# Подготовка Muslingo к App Store и Google Play

Практический статус-план. Разделено на то, что **уже сделано в коде/конфиге**, что
**требует ваших аккаунтов и ключей** (секреты и платные консоли — за вас их сделать
нельзя) и что **отложено** до после первого релиза.

Готовые тексты листинга (название, описания, ключевые слова, категории) вынесены в
отдельный файл **`STORE_LISTING.md`**.

---

## Кратко

Технически приложение готово к сборке релиза: постоянный bundle/app id, нативные
иконки, privacy-манифест iOS, реальные шрифты, аддитивные миграции БД, страница
политики конфиденциальности на `/privacy`. Осталось то, что физически завязано на
**вас**: ключ подписи Android, команда/сертификаты Apple, платные аккаунты сторов,
сборка с прод-URL бэкенда, заполнение форм приватности и возрастного рейтинга,
подстановка реальных юридических данных в политику.

## 2. ТРЕБУЕТ ВАШИХ АККАУНТОВ / КЛЮЧЕЙ (без этого не примут)

Это секреты, платные консоли и юридические данные — их нельзя сгенерировать за вас.

| # | Что нужно | Детали |
|---|-----------|--------|
| **C1** | **Android release keystore** | Release-сборка теперь намеренно падает без upload-ключа и никогда не откатывается на debug-подпись. Вам остаётся: 1) сгенерировать upload-keystore (секрет, храните безопасно, не теряйте пароли): `keytool -genkey -v -keystore ~/muslingo-upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload`; 2) для локальной сборки заполнить `android/key.properties`; 3) для CI добавить GitHub Secrets `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_PASSWORD`, `ANDROID_KEY_ALIAS`. После этого workflow публикует подписанный APK и checksum в GitHub Releases. |
| **C2** | **Apple: Team + сертификаты/провижининг** | В Xcode на машине с **полным Xcode** (здесь только Command Line Tools) выбрать Apple Developer Team, сгенерировать сертификаты и профили, затем `flutter build ipa`. |
| **H2** | **Сборка с прод-URL бэкенда** | Без `--dart-define` `apiBaseUrl` = localhost и регистрация/вход/синк **отключены**. Собирать так: `flutter build appbundle --release --dart-define=MUSLINGO_API_URL=https://muslingo-mobile.vercel.app` (и аналогично для iOS). Бэкенд на Vercel уже развёрнут. |
| — | **Аккаунты разработчика** | Google Play Console — **$25 разово**; Apple Developer Program — **$99/год**. |
| — | **Data safety (Google) / App Privacy (Apple)** | Черновик ответов ниже (раздел 4). Заполняете и отправляете вы в консолях. |
| — | **Возрастной рейтинг** | Пройти анкету рейтинга: контент образовательный/религиозный, без нежелательного → **4+ (Apple) / Everyone (Google)**. |
| — | **Юридические данные в политику** | Подставить в `PRIVACY_POLICY.md` (и в опубликованную страницу) реальные: юрлицо/ИП, страну, контактный email поддержки, дату вступления в силу. Желательно — проверка юристом. |

## 3. ОТЛОЖЕНО (Low — можно после первого релиза)

- Настроить CI-скрипт сборки с зашитым `--dart-define` (чтобы прод-URL не забывался руками).
- Скриншоты для листингов — снимает **владелец** с реального прогона приложения
  (список экранов и размеров — в `STORE_LISTING.md`); автоматически их не сгенерировать.
- Локализация листинга под доп. языки (сейчас основной — русский).
- `Muslingo+` (подписка) — в приложении помечена как «готовится», оплата не запущена;
  для первого релиза монетизации нет, IAP в сторах заявлять не нужно.

---

## 4. Data safety / App Privacy — черновик по фактическим данным

- **Аутентификация:** email + пароль. Регистрация **необязательна** — приложением
  можно пользоваться как гость (прогресс тогда только на устройстве). **Соц-входа
  (Apple/Google) нет.** Пароль хранится только в виде криптографического хеша.
- **Собираем:** email и имя (для аккаунта); учебный прогресс; данные push-подписки
  (для напоминаний); распознанный **текст** речи (для проверки произношения); IP в
  логах (безопасность/антифрод).
- **НЕ собираем:** геолокацию, контакты, фото, рекламные id. Нет рекламы и сторонних
  трекеров (`NSPrivacyTracking=false`).
- **Аудио голоса НЕ хранится** — распознавание выполняется средствами ОС на устройстве,
  наружу уходит только распознанный текст.
- **Активных покупок нет** (`Muslingo+` ещё не запущен).
- Данные шифруются при передаче (HTTPS). **Удаление аккаунта — в приложении** (Настройки).

## 5. Порядок запуска (рекомендация)

1. **Сгенерировать Android keystore** (C1) → скопировать `android/key.properties.example`
   в `android/key.properties` и вписать пути/пароли (release-подпись уже разведена в `build.gradle`).
2. Собрать **Android AAB** с `--dart-define=MUSLINGO_API_URL=…` (H2) → внутреннее
   тестирование в Play Console (быстрее, чем Apple).
3. Параллельно: залить листинги из `STORE_LISTING.md`, снять скриншоты, заполнить
   Data safety, подставить юр-данные в политику.
4. **iOS** — после Apple Developer аккаунта (C2) и на машине с полным Xcode.
